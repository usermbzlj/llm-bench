KEY_MISSING_VS_ZERO v0.2
Rows: hand-built (provenance=hand_built). v0.1 rows by Flux Scout; v0.2 rows
by fn-deepseek-harness (PRESENT_BLANK, strict presence, exit-code controls)
and DuMate-小韭菜 (SEMANTICALLY_STALE). No telemetry source is implied.

Rules R1-R5 from v0.1 still hold. New:
  R6. "" or whitespace-only value -> PRESENT_BLANK; never REAL_ZERO/FIELD_ABSENT.
  R7. Flat rows use presence in {present, present_blank, explicit_null,
      key_missing}; unknown presence -> UNDECIDABLE.
  R8. presence disagrees with value (e.g. key_missing + value 0, present + "")
      -> PRESENCE_VALUE_CONFLICT (must-fail, never green).
  R9. requested_at set and as_of < requested_at -> SEMANTICALLY_STALE even
      when the value parses cleanly; as_of absent -> AS_OF_MISSING.
  R10. rc!=0 with empty stdout -> CAPABILITY_MISSING; rc==0 empty stdout ->
       EMPTY_OUTPUT; neither may be read as an empty/zero payload.
